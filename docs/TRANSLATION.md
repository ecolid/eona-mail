# 翻译预算与阅读优先

原邮件和HTML文字节点结构保持，参考上下文只帮助理解，不作为待翻译输出预留。每次模型请求继续先检查最大输出预算，不能通过去掉门禁恢复可用性。

后台预译保留新信分类余量，并另给手动阅读翻译保留默认1500 neurons，可由AI_TRANSLATE_MANUAL_RESERVE配置（显式0仍保留）。预算总上限AI_DAILY_NEURONS保持；手动请求仍受总预算约束。缓存命中无需新模型调用，后台暂停不阻断已缓存译文。

预算拒绝返回429及budget中的used、limit、required、remaining、reset_at。remaining大于0表示不足以承接当前请求，不能写成已用尽；reset_at按实际UTC日边界生成。失败保留原文和已完成节点，下一次请求继续复用。

当本地预算在调用前拒绝整批时，翻译拆成小批继续处理可承接的节点。上游失败后的不明用量继续保留当日预留。缓存只把相邻已缓存原文作为额外参考，避免重复发送正在翻译的片段。编号、金额和网址校验失败时，合并补译受影响段落的短语，由程序复原被保护内容。其他已通过校验的段落直接入缓存。

参数与用量按当前模型核对，平台参考[Workers AI配额](https://developers.cloudflare.com/workers-ai/platform/pricing/)与[模型合同](https://developers.cloudflare.com/workers-ai/models/llama-3.3-70b-instruct-fp8-fast/)。本地账本不是账号其他服务的全量用量证明。

永久回归在test-inline-translation.mjs：大只读上下文的输出预算、自动／手动分工、总预算耗尽后的缓存、429真实余量及原文保留。界面继续沿原翻译／重试／切回原文状态，不重排阅读页。

## 实例账号额度和用量回执

实例可提供 `TRANSLATION_QUOTA({day,booked,refresh})`，返回同一 UTC 日的账号已用额度、日上限、读取时 Mail 已记用量与有效状态。正常沿用集成方可用快照。旧本地上限或平台余额即将拦住当前请求时要求刷新。账号读数可能延迟，后续新增的本地已记用量及仍在途的占位计入本次判断。自动预译继续留出分类和手动翻译的独立额度。来源缺失或刷新失败时使用本地上限，已有平台观测到较高用量依然有效。

提供 `TRANSLATION_RECEIPTS` 的实例在发送前将请求号和预算占位一起落库。可靠结果写入实际用量并释放占位。确定未开始推理的拒绝直接释放。响应未到达时，实例后台按请求号查回，并在同一事务内结算和移除待查记录。平台未确认的请求保留到所属账日结束。未配置集成的实例继续沿用本地预算。无需把邮件正文或模型回复放进回执。

## 非中文来信与旧译文

Mail 阅读入口与后台预译使用同一文字判定。新收件按归档 ID 登记，分类尝试次数不会阻断翻译。HTML 正文按可见节点切分，长节点拆成可续译的分段。短正文和仅有非中文主题的来信同样进入队列。中文片段与已保护的标识保留原样。模型回显明显的外语正文会进入修复或重试。

后台先复用同一阅读节点缓存。额度不足保留待处理状态，单封临时失败安排重试，队列仍可处理其他到期待办。历史完整译文核对原文和译文后可以直接在原邮件打开，截断或原文不符的旧译文不作为全文完成凭据。
